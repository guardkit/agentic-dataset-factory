# Runbook: Upload the fine-tuned GCSE English Tutor (Gemma-4 MoE) to Hugging Face

**Purpose:** Take the artefacts produced by the GCSE-tutor fine-tune and publish them to the Hugging Face Hub as two repos: a **weights repo** (merged-16bit + LoRA adapter) and a **GGUF repo** (Q4_K_M + BF16 + mmproj + Modelfile).
**Machine:** Dell DGX Spark GB10 (`promaxgb10-41b1`). Uploads are bandwidth-bound; run from the box that already holds the 49 GB merged weights, not over wifi from a laptop.
**Driver script:** `scripts/push_to_hf.py` (in this repo). Each subcommand maps to one phase below. The `gcse-tutor` `DomainSpec` is already present in that script — no code change needed.
**Duration:** ~5-30 min wall-clock per artefact depending on upstream bandwidth. `hf_transfer` saturates a gigabit link.
**Prerequisite:** A successful fine-tune — non-empty `lora-adapter/`, `merged-16bit/`, `gguf_gguf/` under the artefact root below.
**Companion:** This is the GCSE-tutor counterpart of `domains/architect-agent/RUNBOOK-huggingface-upload.md`. The two runbooks are deliberately near-identical; only the **Inputs** block and the artefact-specific notes differ.

## Inputs

```bash
DOMAIN="gcse-tutor"                                 # matches the DomainSpec slug in push_to_hf.py
ARTEFACT_ROOT="$HOME/fine-tuning/output/gcse-tutor-gemma4-26b-moe-2026-04-18"
HF_OWNER="RichWoollcott"                            # confirm with `hf auth whoami` (case matters for some Hub APIs)
REPO_WEIGHTS="${HF_OWNER}/gcse-tutor-gemma4-26b-moe"
REPO_GGUF="${HF_OWNER}/gcse-tutor-gemma4-26b-moe-GGUF"

REPO_DIR="$HOME/Projects/appmilla_github/agentic-dataset-factory"
PUSH="python $REPO_DIR/scripts/push_to_hf.py"

# Staging dir for rendered model cards. ARTEFACT_ROOT is root-owned (created
# by the Docker training container), so we cannot write inside it. Use a
# user-writable sibling under ~/fine-tuning/ instead.
STAGING="$HOME/fine-tuning/staging/${DOMAIN}"
mkdir -p "$STAGING"
```

> **Two GCSE-tutor artefact dirs exist under `~/fine-tuning/output/`.** Use
> `gcse-tutor-gemma4-26b-moe-2026-04-18` (the Gemma-4-26B-A4B MoE run that
> matches the `gcse-tutor` `DomainSpec`). The older `gcse-tutor-gemma4-31b-2026-04-10`
> is a superseded 31B run — do **not** upload it.

The artefact tree this runbook expects:

```
$ARTEFACT_ROOT/
├── lora-adapter/           1.9 GB — adapter_model.safetensors + tokenizer + chat_template
├── merged-16bit/            49 GB — full base + LoRA merged, vLLM-ready (2-shard safetensors)
├── gguf/                    -     — duplicate safetensors copy (GGUF conversion source — DO NOT upload)
├── gguf_gguf/               18 GB — GGUF files: Q4_K_M, BF16 shard(s), mmproj, Modelfile
├── checkpoint-*/                  — intermediate checkpoints (30/200/400/434 — do NOT upload)
└── README.md                      — TRL-autogenerated; we overwrite with a richer card in Phase 1
```

## Phase 0: Pre-flight gates

Read-only. Run before any repo creation or upload.

### 0.1 Artefacts present and non-empty

```bash
for sub in lora-adapter merged-16bit gguf_gguf; do
    if [ ! -d "$ARTEFACT_ROOT/$sub" ] || [ -z "$(ls -A "$ARTEFACT_ROOT/$sub" 2>/dev/null)" ]; then
        echo "MISSING: $ARTEFACT_ROOT/$sub"; exit 1
    fi
done

test -f "$ARTEFACT_ROOT/lora-adapter/adapter_model.safetensors" || { echo "MISSING adapter weights"; exit 1; }
test -f "$ARTEFACT_ROOT/merged-16bit/model.safetensors.index.json" 2>/dev/null \
    || ls "$ARTEFACT_ROOT/merged-16bit/"*.safetensors > /dev/null 2>&1 \
    || { echo "MISSING merged-16bit safetensors"; exit 1; }
ls "$ARTEFACT_ROOT/gguf_gguf/"*.gguf > /dev/null 2>&1 \
    || { echo "MISSING gguf files"; exit 1; }

echo "PASS — artefacts present"
du -sh "$ARTEFACT_ROOT"/{lora-adapter,merged-16bit,gguf_gguf}
```

Expected (gcse-tutor 2026-04-18 run, verified on this upload):
- `lora-adapter`: 1.9 GB
- `merged-16bit`: 49 GB — `model-0000{1,2}-of-00002.safetensors` + index + tokenizer/processor/chat_template
- `gguf_gguf`: 18 GB

> **Known artefact quirk — GGUF BF16 split is incomplete.** The 2026-04-18
> `gguf_gguf/` contains `gemma-4-26b-a4b-it.Q4_K_M.gguf` (16.8 GB),
> `gemma-4-26b-a4b-it.BF16-00002-of-00002.gguf` (582 MB),
> `gemma-4-26b-a4b-it.BF16-mmproj.gguf` (1.2 GB) and `Modelfile` — but **no
> `BF16-00001-of-00002.gguf`**. The BF16 split is therefore unusable as a full
> BF16 model; only **Q4_K_M** is a complete, loadable quantisation. This is a
> pre-existing fine-tune output issue, not an upload error. Q4_K_M + Modelfile
> are uploaded and verified; if a complete BF16 GGUF is needed, re-export it
> from `merged-16bit/` and re-push.

### 0.2 Disk free on the cache mount

```bash
df -BG ~/.cache/huggingface/ | awk 'NR==2 {gsub("G","",$4); print; if ($4+0 < 60) print "WARN: <60GB free on HF cache mount"}'
```

### 0.3 HF auth configured with a *write* token

The login state in Firefox doesn't help — the CLI needs its own token.

```bash
pip install -U "huggingface_hub>=1.8" hf_transfer    # if needed
hf auth whoami    # should print: RichWoollcott
$PUSH whoami      # should match — confirms the same token the script will use
```

If "Not logged in": `hf auth login` and paste a fine-grained write token from
https://huggingface.co/settings/tokens (scope "Write access to all repos").

### 0.4 Repo-name sanity

| Check | What to do |
|---|---|
| HF_OWNER matches your username | `$PUSH whoami` — compare the `name` field |
| Repo IDs don't already exist as someone else's | Visit `https://huggingface.co/$REPO_WEIGHTS` — a 404 means you're clear |
| Public visibility is OK | Default is public; pass `--private` to `create-repo` if not |

### 0.5 Decision matrix

| All gates pass | → | Proceed to Phase 1 |
| Artefact missing or empty | → | **STOP**. Investigate the fine-tune output |
| Token is read-only / not configured | → | **STOP**. `hf auth login` with a write token |
| Repo name collides with a stranger | → | **STOP**. Pick a different name, update Inputs |

## Phase 2: Create the repos

Idempotent (`exist_ok=True`). Safe to re-run.

```bash
$PUSH create-repo --repo-id "$REPO_WEIGHTS"
$PUSH create-repo --repo-id "$REPO_GGUF"
```

Dry run: append `--dry-run`.

## Phase 3: Upload LoRA adapter (~1.9 GB, ~2 min)

Smallest artefact → upload first. Validates auth, chunking, and `hf_transfer`
end-to-end before committing 30+ minutes of bandwidth to the 49 GB upload.

```bash
$PUSH push \
    --repo-id "$REPO_WEIGHTS" \
    --src "$ARTEFACT_ROOT/lora-adapter" \
    --path-in-repo "lora-adapter" \
    --message "upload LoRA adapter"

$PUSH verify --repo-id "$REPO_WEIGHTS" \
    --require "lora-adapter/adapter_config.json" \
              "lora-adapter/adapter_model.safetensors"
```

> Note: this GCSE adapter folder ships `chat_template.jinja` but **not** a
> standalone `chat_template.json` — verify on `adapter_config.json` +
> `adapter_model.safetensors` (the architect runbook also checked
> `chat_template.jinja`; it's present here too but the two essential files
> above are the reliable gate).

Expected speed: 400-600 MB/s with `hf_transfer` on a gigabit link. <5 MB/s means
`hf_transfer` is not active — check `pip show hf_transfer` and that
`HF_HUB_ENABLE_HF_TRANSFER=1` is exported.

---

## Phase 4: Upload merged-16bit weights (~49 GB, ~15-25 min)

Slowest single step. Detach into `tmux`/`screen` (or run as a background job)
so an SSH/session drop doesn't kill it.

```bash
tmux new -s hf-push-weights "$PUSH push \
    --repo-id $REPO_WEIGHTS \
    --src $ARTEFACT_ROOT/merged-16bit \
    --include 'config.json' 'tokenizer*' 'processor*' 'chat_template*' 'special_tokens*' '*.safetensors' '*.safetensors.index.json' '*.txt' \
    --exclude '__pycache__/*' \
    --message 'upload merged-16bit weights'"
# Reattach: tmux attach -t hf-push-weights   |   Detach: Ctrl-B then D
```

The `--include` allow-list avoids uploading stray shards or optimizer state.

After completion:

```bash
$PUSH verify --repo-id "$REPO_WEIGHTS" \
    --require "config.json" \
              "tokenizer_config.json" \
              "model.safetensors.index.json" \
              "*.safetensors"
```

Push the model card **last** so it isn't overwritten by anything in `merged-16bit/`:

```bash
$PUSH push \
    --repo-id "$REPO_WEIGHTS" \
    --src "$STAGING/README-weights.md" \
    --path-in-repo "README.md" \
    --message "add model card"
```

---

## Phase 5: Upload GGUF repo (~18 GB, ~7-12 min)

```bash
tmux new -s hf-push-gguf "$PUSH push \
    --repo-id $REPO_GGUF \
    --src $ARTEFACT_ROOT/gguf_gguf \
    --include '*.Q4_K_M.gguf' 'Modelfile' \
    --message 'upload Q4_K_M GGUF quantisation'"
```

> **Use `'*.Q4_K_M.gguf'`, not `'*.gguf'`.** A bare `*.gguf` glob would also
> sweep up the **incomplete** BF16 split (`BF16-00002-of-00002.gguf` with no
> `00001`) and the `BF16-mmproj.gguf`. Only the **Q4_K_M** quant is a complete,
> loadable artefact — publish that alone. If a complete BF16 GGUF is needed
> later, re-export it from `merged-16bit/` first, then push it explicitly.

After upload, write the GGUF repo card and verify:

```bash
$PUSH push \
    --repo-id "$REPO_GGUF" \
    --src "$STAGING/README-gguf.md" \
    --path-in-repo "README.md" \
    --message "add model card"

$PUSH verify --repo-id "$REPO_GGUF" \
    --require "*.Q4_K_M.gguf" "Modelfile" "README.md"
```

## Failure modes & recovery

| Symptom | Cause | Fix |
|---|---|---|
| `Hugging Face auth not configured` | No CLI token or read-only token | `hf auth login` with a write token; re-run |
| Upload stalls at ~0 KB/s | `hf_transfer` not active | `pip install -U hf_transfer`; export `HF_HUB_ENABLE_HF_TRANSFER=1` |
| `RepositoryNotFoundError` on push | Phase 2 skipped or repo-ID typo | Re-run `create-repo`, retry the push |
| merged-16bit push fails partway | Network blip; uploader is resumable | Re-run the same `push` — uploaded files are skipped |
| `429 Too Many Requests` | Hub rate-limit on many small files | Wait 30s, retry |
| `verify` reports missing file after a successful upload | Hub eventual-consistency lag | Wait 30s, re-run `verify` |
| Card shows raw `{display_name}` | Card pushed before re-rendering after a DomainSpec edit | Re-render and re-push README only |

## Phase 7 (open / followup): Training-data upload

Deliberately **not** automated. The GCSE corpus may incorporate set-text
quotations (e.g. *Dr Jekyll and Mr Hyde*, AQA anthology poems) that fall
outside fair use; a license review must precede any public dataset release.
Until then the **synthetic-pipeline source code** (this repo) is the published
reproduction recipe and the **weights** are the redistributable artefact.

## Quick-reference (all-in-one)

Once Phase 0 is green and Inputs are set:

```bash
# 1. Render cards
$PUSH render-card --domain "$DOMAIN" --repo-id "$REPO_WEIGHTS" --out "$STAGING/README-weights.md"
$PUSH render-card --domain "$DOMAIN" --repo-id "$REPO_GGUF"    --out "$STAGING/README-gguf.md"

# 2. Create repos
$PUSH create-repo --repo-id "$REPO_WEIGHTS"
$PUSH create-repo --repo-id "$REPO_GGUF"

# 3. Upload adapter (small; smoke-tests auth + transfer)
$PUSH push --repo-id "$REPO_WEIGHTS" --src "$ARTEFACT_ROOT/lora-adapter" --path-in-repo "lora-adapter"

# 4. Upload merged-16bit (long; in tmux)
tmux new -s hf-push-weights "$PUSH push --repo-id $REPO_WEIGHTS \
    --src $ARTEFACT_ROOT/merged-16bit \
    --include 'config.json' 'tokenizer*' 'processor*' 'chat_template*' 'special_tokens*' '*.safetensors' '*.safetensors.index.json' '*.txt'"

# 5. Upload GGUF (in tmux) — Q4_K_M only; '*.gguf' would sweep up the incomplete BF16 split
tmux new -s hf-push-gguf "$PUSH push --repo-id $REPO_GGUF \
    --src $ARTEFACT_ROOT/gguf_gguf --include '*.Q4_K_M.gguf' 'Modelfile'"

# 6. Push cards last
$PUSH push --repo-id "$REPO_WEIGHTS" --src "$STAGING/README-weights.md" --path-in-repo "README.md"
$PUSH push --repo-id "$REPO_GGUF"    --src "$STAGING/README-gguf.md"    --path-in-repo "README.md"

# 7. Verify
$PUSH verify --repo-id "$REPO_WEIGHTS" \
    --require "config.json" "tokenizer_config.json" \
              "model.safetensors.index.json" "*.safetensors" \
              "lora-adapter/adapter_model.safetensors" "README.md"
$PUSH verify --repo-id "$REPO_GGUF" --require "*.Q4_K_M.gguf" "Modelfile" "README.md"
```
