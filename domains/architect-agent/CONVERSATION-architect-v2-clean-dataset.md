## Decision (2026-06-23)

**Build the internalised architect; defer the grounded architect.** Knowledge in the
weights, no inference RAG, no citations — the only version that is commercially clean now
(no books at inference) and the one that makes the fabrication problem vanish rather than
needing a fix. The **grounded architect** (real tool-use over a clean, updatable corpus,
with honest citations) is a genuinely better but harder product, deferred to a later phase
gated on: a clean corpus, captured own-data, and **execution-grounded** tool-use training
(SFT-on-traces is what produced the fabrication — see below — so the grounded version needs
real tool execution in the loop, not more static traces).

A clean-corpus RAG that keeps the current pre-retrieve-and-inject plumbing and only swaps
the corpus was considered and **rejected as a kludge** — it relegalises a workaround for a
model defect without removing the workaround.

## As-built findings (confirmed 2026-06-23, grounded in the repo + evidence audits)

**The retrieval corpus is verbatim copyrighted book text.** `architect-books-v1` is 35,208
literal chunks sliced from the 19 books (byte-for-byte matches on sampled chunks, no
synthetic content). It is **live in the architect greenfield path**: the orchestrator
unconditionally pre-retrieves 8 extracts and injects them into the Player's first user
message with a **mandatory `[book_id: chunk N]` citation instruction**, every session. This
is the commercial exposure — verbatim book prose injected into a product's working context
and cited in deliverables.

**The training data is already citation-free and tool-free.** `train.jsonl` (894 records)
and the prompt the SLM was trained on (`roles/architect/prompts/player_trained.md`) carry
0/894 `book_id` citations and no tool-call protocol — just the expert-architect persona.
The model learned to reason from internalised knowledge.

**Fabrication is therefore serving-side, not in the weights.** The model invents `book_id`
citations ("imagined RAG", e.g. a non-existent `DDD_Vaughn_Evans_2013`) only when a serving
component *demands* citations it was never taught to produce: the live `player.md` regime
(mandatory `architecture_knowledge_query` + `[book_id: chunk N]`) and the injection block's
mandatory-citation instruction. The local/trained path already serves the clean
`player_trained.md`, so on that path the **injection is the only citation pressure** —
removing it *eliminates* the fabrication (the model has no citation habit to fall back on),
it does not re-enable it.

**The synthetic knowledge layer was tried and abandoned.** A generated `knowledge.jsonl`
existed (357 KB) and is now 0 bytes (`output_backup_pre_rerun/` confirms a deliberate
re-run). It was inadequate — sparse and reasoning-heavy (think-blocks + prose, not dense
reference content), generated by the local workhorse on the books. So "repoint the RAG at
the synthetic layer" is not an available drop-in.

**Fine-tune-only already worked.** The 2026-05-06 OWUI deployment served the architect
fine-tune with no retrieval and tested well — evidence the internalised baseline may already
be good.

## Open questions carried into the plan

- **Structured-output provenance (the Phase 0 question).** `player.md` carries the full
  Conversation Starter output scaffolding (C4, DDD context map, ADR Preferred Directions,
  assumptions JSON) that `player_trained.md` does **not**. Unconfirmed whether the trained
  model produces that deliverable from its training data or whether the structure came from
  `player.md`. `player_trained.md` is a **frozen, hash-locked artefact** tied to the
  training snapshot — it cannot be edited to add structure without re-snapshotting/retraining.
- **Citation policy for the v2 fine-tune.** Decide: no source citations (reason from
  internalised knowledge — cleanest for the chosen architecture), or, for the deferred
  grounded version, cite only real injected extracts and never fabricate. Either way, v2
  training data must not reproduce the emit-tool-call-then-fabricate pattern.
- **Book-free golden set.** Does one exist for the eval? If not, build one; its provenance
  must also be book-free.
- **Clean external corpus + own-outputs** are repurposed as a *training-time* input
  (grounding v2 generation, and the later flywheel), **not** an inference RAG.

---

## Principles applied

Distillation (strong Player → small shipped model) is the SLM playbook, not a betrayal of
it — the "small models" thesis governs the *production* model, not the one-time
*manufacturing* model. DECISION-DF-001 (no cloud on the serving critical path) is not
breached by a bounded, attended, one-time generation run. Building a second factory mode now
is exemplar-before-template. Harvesting validated own-outputs is harvest-don't-author — and
the moat.
